把 AM32 移植到 MCXA153VFM：外设适配与六步无感控制

以 A153 固件源码为主线，记录 AM32 在 MCXA153VFM 上的输入捕获、六步换相、FlexPWM、ADC 与 Flash 适配；样机已落地，负载测试尚未进行。

UPDATED 2026.10.23BLDCAM32NXP

把 AM32 移植到一颗新的 MCU，工作重点不是改几个芯片宏，而是把固件依赖的实时外设重新接起来：输入信号要能准确解码，三相 PWM 要符合目标芯片的通道结构，反电动势过零事件要能推进换相，ADC 数据和参数存储也要进入 AM32 原有的控制流程。

本文围绕工程中的 CUSTOM_A153VFM target 展开。MCXA153VFM 样板已经制作出来，固件也已在实物板上落地运行；负载测试还没有做，因此本文不讨论额定电流、持续功率、效率或温升指标。文章中的控制逻辑和软件引脚配置以现有源码为准，原理图元件标注只作为设计阶段的记录，不据此断言实际焊接器件的型号或连接状态。

移植边界：保留控制框架，重写 MCU 适配层

AM32 的通用代码已经包含油门输入处理、启动与使能状态、六步换相状态机、参数管理和遥测等流程。移植时，尽量保留这些上层逻辑，再由 A153 平台层提供相应的计时器、比较器、PWM、ADC、DMA 和 Flash 能力。这样做的关键是让硬件事件继续落在 AM32 预期的接口上，而不是在每个控制流程里散落一套新的芯片寄存器操作。

当前工程的构建入口选择 CUSTOM_A153VFM，再通过 HARDWARE_GROUP_NXP_MCXA153 选入 A153 外设实现。代码职责大致分布在以下位置：

层次 主要源码 负责内容
AM32 控制流程 AM32-main/Src/main.c、signal.c、dshot.c 输入映射、使能状态、占空比斜坡、换相调度和遥测
芯片外设层 AM32-main/Mcu/a153/Src/peripherals.c、timers.c 时钟、引脚复用、计时器与平台外设初始化
三相输出 Mcu/a153/Src/flexpwm.c、phaseouts.c 三组互补 PWM、死区、扇区输出选择与浮空相屏蔽
过零与中断 Mcu/a153/Src/comparator.c、mcxa153_it.c 比较器输入切换、过零边沿和定时换相中断

输入捕获：从引脚边沿到油门量

A153 target 将输入捕获配置到 P1.2，并把该引脚复用给 CTIMER0。计时器捕获输入边沿后，DMA 将捕获寄存器中的时间值搬进缓冲区；DMA 完成中断调用 doDshotCorrection() 和 transfercomplete()，随后置位 input_ready，由主循环继续处理数据。

这条路径同时服务 DShot 和 PWM 输入。DShot 路径需要把捕获时间恢复成数据位、检查帧并解析命令；PWM 路径则根据捕获到的高电平时间计算伺服脉宽。输入识别完成后，AM32 的输入处理会做范围映射、死区和方向相关处理，生成 newinput、adjusted_input 等状态量，最后得到控制占空比所需的 input。A153 的工作主要是提供稳定的计时基准和 DMA 采样，不改变上层“识别协议—映射指令—更新控制量”的结构。

源码把 CTIMER0 的功能时钟设置为 96 MHz，并将两个捕获寄存器分别用于边沿时间记录。DMA 还可以避免每个边沿都进入软件中断，使协议解码集中在一帧数据采集完成之后。对 MCU 移植而言，这比简单地把旧平台的 GPIO 中断换成另一个中断更接近 AM32 原有的输入处理模型。

六步无感换相：比较器事件驱动扇区推进

AM32 在这里使用的是六步无感换相，不是 FOC。一个电周期拆成六个换相扇区；每个扇区选择两相形成驱动电流路径，剩余一相作为浮空相观察反电动势。MCXA153VFM 的 CMP0/CMP1 输入通过 changeCompInput() 随当前扇区切换到应观察的相，并根据当前预期方向设置上升沿或下降沿中断。

检测到有效过零后，interruptRoutine() 会暂时屏蔽相位比较器中断，记录过零时间，并启动换相等待计时。等待时间由相邻过零周期估算，并结合 temp_advance 或自动提前角参数计算。CTIMER1 到期后进入 PeriodElapsedCallback()，推进到下一个扇区，再重新选择浮空相和比较器输入。这个“过零—延时—换相—切换观察相”的闭环，是平台适配中最需要保持时序关系的一部分。

比较器中断里还做了时间合理性检查：若当前间隔计数过短，且比较器电平并非预期边沿，就清除事件而不推进换相。旧式轮询路径则会在控制循环里连续读取比较器状态，按 filter_level 对电平进行采样，再累计满足条件的次数。两条路径共同服务启动和运行中的换相判定；具体使用路径会受 AM32 状态及 target 配置影响。

FlexPWM：三组互补输出与六步状态映射

flexpwm.c 为三相初始化三个同步子模块，配置互补输出、死区计数器和缓冲寄存器同步更新，再把每个子模块的两路输出复用到 GPIO。源码注释给出的 FlexPWM 时钟与重载配置对应约 24 kHz 的 PWM 频率，target 的 DEAD_TIME 配置值为 70。这里的频率和计数值描述的是固件配置，不等同于示波器实测的门极波形和有效死区。

真正容易移植错的是“PWM A/B 通道”和“AM32 高侧/低侧状态”之间的对应关系。通用 phaseouts.c 默认把 A/B 通道按既有平台习惯解释；A153 target 定义了 PWM_HIGH_LOW_SWAPPED，因此在扇区输出时同步调整 PWM 波形源选择与 MASK 位映射。其效果是让三相状态表仍然可以沿用 AM32 的抽象，而由 target 适配层处理具体通道配对差异。若只改引脚复用，却没有同步修改状态选择和掩蔽位，软件的“浮空相”或“低侧导通”就可能落到另一输出上。

源码中配置的三组互补 PWM GPIO 对为 P3.0/P3.1、P3.8/P3.9 和 P3.10/P3.11。这个列表反映的是 A153 target 的软件资源分配；由于原理图标注和实际焊接情况尚未逐项核对，本文不把这些端口进一步写成已确认的栅极驱动器输入或功率管连接。

电流、电压和温度数据路径

A153 的 LPADC 按命令序列采集电流、电压和片内温度，DMA 通道 1 将结果 FIFO 搬进 ADCDataDMA 缓冲区。DMA 中断更新原始采样变量；AM32 后续处理通过 getSmoothedCurrent() 对电流样本做滑动平均，并对母线电压做 7/8 旧值加 1/8 新值的低通平滑。数据处理在固件的低速控制节拍中触发，避免把换相中断变成繁重的计算路径。

电压和电流的工程量换算使用 targets.h 中的 target 常量。例如，电压换算会结合 ADC 满量程、3.3 V 参考值和 VOLTAGE_DIVIDER；电流换算则结合 ADC 采样、CURRENT_OFFSET 与 MILLIVOLT_PER_AMP。A153 target 当前配置的换算系数，是软件参数而非实测校准结论。它们能说明固件如何把采样值转成遥测和保护逻辑使用的数值，但不能单独证明实际焊接的采样电阻、放大器或分压网络与配置完全一致。

在运行路径中，母线电压可供低压判定和遥测使用；电流值可供 AM32 的电流限制与遥测逻辑使用，是否启用相应限制还取决于参数配置。把 ADC/DMA 的数据搬运、物理量换算和 AM32 参数分开看，能帮助定位问题究竟出在转换链、标定系数还是上层限制条件。

油门斜坡和零油门处理

当前 A153 target 给启动、低转速和高转速阶段分别设置斜坡上限 2/4/14，并把斜坡更新限制在 1 kHz。AM32 的主控制节拍为 20 kHz，因此 ramp_divider 让占空比每 20 次控制循环才允许变化一次。代码根据启动/过零状态及换相间隔选择所处斜坡段，再限制本次目标占空比与上次占空比的差值。写在 EEPROM 中的 max_ramp 设置还可能进一步降低这些上限。

以满量程 2000 计算，若斜坡确实以每秒 1000 次更新、每次最多变化 2、4 或 14 个计数，理想的全量程变化时间约为 1.0 s、0.5 s 和 0.143 s。这个换算只说明数字斜坡的理论上限，不代表电机带载响应时间。

A153 target 还把零油门处理设为滑行关断：占空比回到零后关闭全部相输出，并继续依据转子反电动势跟踪状态；主动短接式制动在这份 target 代码中被屏蔽。这个决定属于当前固件配置和保护策略，不表示对任何特定功率级器件或母线瞬态能力作了测量结论。

Flash 布局与参数保存

MCXA153VFM 芯片具有 128 KiB 物理 Flash；当前 AM32 链接布局只使用低 64 KiB，并按地址把 bootloader、应用和参数区分开：

地址范围 当前固件布局
0x0000–0x3FFF PB2 bootloader
0x4000–0xDFDF AM32 主应用
0xDFE0–0xDFFF 固件名称标记
0xE000–0xFFFF 参数存储区

A153 Flash 擦除扇区为 8 KiB，编程页为 128 B。eeprom.c 使用 ROM Flash API 保存参数：先检查地址、长度和扇区/页几何条件，再擦除参数扇区并校验擦除结果，随后按页边界分段编程和逐段校验。写 Flash 的函数放在 RAM 中执行，避免在擦除或编程期间从同一 Flash 区执行代码。Bootloader 的更新路径也检查写入范围，避免更新命令覆盖 bootloader 区或越过 AM32 当前 64 KiB 布局。

这个分区让应用更新与运行参数各有固定区域，但它依赖链接脚本、应用 target 和 bootloader 对地址的共同约定。换 MCU 时只改应用起始地址是不够的；文件名标记、参数起始地址、ROM API 擦写粒度和 bootloader 接受的升级范围都必须使用一致的布局。

构建结果与当前进度

主固件通过 AM32 的 Makefile 选择 CUSTOM_A153VFM 构建；PB2 bootloader 使用单独的构建目标。2026-10-17 项目构建记录使用 GNU Arm Embedded Toolchain 10.3.1。记录中的主固件占用 29,220 B 的应用程序区域，PB2 bootloader 占用 4,124 B；HEX 地址范围、向量、文件名标记以及合并镜像的地址重叠检查均通过。

构建成功说明 A153 适配层、链接布局和镜像整理可以形成固件产物；它本身不等价于负载能力或器件热性能的证明。当前实物样板已经落地并运行 AM32 固件，负载测试尚未完成，因此本文不标注额定电流或持续功率。

这次移植的技术核心，是让 AM32 原有的控制状态机继续工作，同时在 MCXA153VFM 上重建它依赖的输入捕获、DMA、比较器过零、定时换相、互补 PWM、ADC 和 Flash 参数存储路径。样机已经从源码走到实物运行；硬件型号按实际焊接清单核实，性能指标则以负载测试数据为准。

这篇文章单独复盘 AXDR_L 无刷驱动程序，而不是再从头讲一遍 FOC 理论。当前工程源地址是 C:\Users\35053\Desktop\Class\控制设计\AxDr_L\3.AXDR_X7_Speedloop。它的目标很明确：把 X7/Simulink 里的速度环和电流环思路，落到 AXDR-L 功率板、STM32G474、DJI M2006 减速无刷电机和 MT6816 磁编码器组成的实机平台上。

程序定位

这个工程不是一个通用电调固件，也不是单纯的开环转电机 Demo。它更像一个“可验证的 FOC 闭环实验平台”：先用 Simulink 和桌面脚本确定控制结构，再在板端拆成 20 kHz 电流环、1 kHz 速度环、编码器电角度、PWM/SVPWM、保护停机、LCD 显示、USB CDC 命令和 Python 自动化测试。

程序最终解决的是三个问题：

  1. 电机能不能在真实 AXDR-L 功率级上闭环运行。
  2. 速度环、电流环、编码器和 PWM 是否能按固定时序协同。
  3. 结果能不能被日志、图像和脚本复现，而不是只靠肉眼判断“转起来了”。

硬件与关键参数

当前源码里的主要约束集中在 User/motor/axdr_motor_config.h：

项目 当前值 含义
主控 STM32G474RETx 使用 TIM1、ADC injected、SPI、USB CDC 等外设
母线电压 24.0 V nominal 软件保护窗口为 18.0–30.0 V
电机 DJI M2006 P36 36:1 减速箱，输出轴目标速度用于测试
极对数 7 机械角到电角度换算的核心参数
相电阻 / 相电感 0.461 ohm / 64.22 uH 用于 Id/Iq 电流环 PI 整定
输出轴转矩常数 0.18 N*m/A 速度环前馈和负载估计参考
编码器 MT6816, 14 bit 当前按高速轴安装处理
电流限制 8.5 A soft / 10.5 A derate-zero 300 rpm 阶段源码值
电流环限制 500 Hz 带宽，8.5 V 输出限幅 同时受Vbus/sqrt(3) 约束

这组参数的重点不是“数值看起来完整”，而是它们都落到了真实控制链路里：电阻电感决定 PI 初值，母线电压决定电压矢量上限，减速比决定速度和电角速度换算，编码器位置决定 Park 变换角度。

软件结构

工程里最关键的文件可以按职责分层看：

文件 作用
Core/Src/main.c 外设初始化、主循环、TIM3 速度 tick
Core/Src/tim.c TIM1 三相 PWM、CH4 ADC 触发、TIM3 1 kHz tick
Core/Src/adc.c ADC1 三相电流和 ADC2 母线电压采样
User/motor/axdr_motor_config.h M2006、MT6816、限流、电流环参数
User/motor/foc_calc.c Clarke、Park、inverse Park、SVPWM/SVM
User/motor/foc_drv.c 电流换算、Id/Iq PI、电压限幅、PWM start/stop
User/motor/foc_ctrl.c ADC injected 回调和旧 PMSM 状态机入口
User/motor/live_speed_test.c 实机速度环、profile、角度校准、保护、VOFA 输出
User/motor/speed_display.c ST7789 状态显示和 0–500 rpm 曲线
tools/run_hs300_test.py 100/300 rpm 自动化采集与验收

这套拆分比较清楚：底层 FOC 只负责“给定 Id/Iq 和电角度，算出三相 PWM”；速度环只负责把目标 rpm 和实际 rpm 变成 Iq_ref；测试层只负责 profile、命令、停机和日志。这样后续换 profile 或调参数时，不需要改 PWM 和采样底层。

控制链路

实机闭环路径可以压缩成一句话：

电流环由 ADC1 injected 转换完成回调触发，避免 ADC2 母线电压采样再触发一次 FOC，导致一个 PWM 周期内重复计算。Id/Iq PI 仍沿用仿真里的 Kp=L*wc、Ki=R*wc 主线，但在实机中增加了积分限幅、电压矢量限幅和 PWM 使能状态约束。

速度环运行在 1 kHz。它不直接碰 PWM，而是生成 Iq_ref，再交给 20 kHz 电流环执行。后期 100/300 rpm 调参时，程序引入了低速、中速、高速三段参数区，并为每段单独设置超速刹车电流、刹车增益和 slew rate。这个方向比单纯把速度滤波变慢更有效，因为慢滤波会把相位滞后带进闭环，让 100 rpm 保持反而变差。

人机交互与安全停机

当前交互有两条入口：USB CDC 字符命令和板载四个按键。USB 命令包括 G/U/V/W/P/R/T/L/M/H/S/X/+/-，覆盖自动序列、100 rpm 脉冲/斜坡/阶跃、300 rpm 脉冲/斜坡/阶跃、低速保持、中速保持、高速保持、固定 80 rpm、停止和手动增减速。

按键逻辑已经改成更适合现场测试的“选中后执行”：

按键 引脚 当前作用
Key1 PC9 切换到上一个 LCD 命令
Key2 PC8 切换到下一个 LCD 命令
Key3 PC7 执行当前 LCD 选中的命令
Key4 PC6 停止电机，关闭 PWM/R_EN

安全路径也贯穿在程序里：X 命令、Key4、abort、fault 都会进入停机流程，清掉速度环状态，关闭三相 PWM，并把 R_EN 拉低。自动化脚本也会在测试开始前先发 X，结束后再发 X，并额外采集 idle 数据确认 PWM=0、R_EN=0、ref_rpm=0。

复现时要固定的证据等级

这个工程的验证结果需要区分“源码可读”“工程可编译”“固件已下载”“串口有输出”和“电机真实闭环运行”几个等级。Keil 工程能解析、C 文件能通过语法扫描，只能说明软件文件和依赖关系基本完整；HEX 成功生成，说明编译链路通过，但不能证明板上的固件已经更新；串口能够读到 JustFloat 帧，说明 USB CDC 或虚拟串口链路有输出，但如果通道数、参考速度和状态字段仍然是旧版本，就不能把它当成新固件验证。

因此每次复现实验都应保存一组最小证据：工程配置和编译日志、烧录后的版本标记、串口端口与波特率、VOFA 帧通道数量、测试命令、原始日志以及结束时的安全状态。当前验证记录中，COM37 用于 STM32 虚拟串口，COM10 是 WCH-Link 备用串口；旧固件曾经输出 7 通道、600 rpm 参考值，而新测试预期输出 10 通道并包含 MT6816 raw、角度和状态字段。这个差异本身就是判断“板上到底运行了哪个版本”的重要证据。

推荐的实机调试顺序

第一步是静态检查和低能量上电。确认 24 V 输入处于软件允许的 18-30 V 窗口内，先不接机械负载，用限流电源观察 5 V、3.3 V、功率级驱动供电和 MCU 温升；同时确认 R_EN 默认拉低，三相 PWM 在复位和主循环未启动时保持关闭。第二步是读取 MT6816 原始角度，检查 SPI 返回值是否随手动转动单调变化，确认方向、零点和 14 bit 数据右移方式一致。

第三步是做电流采样和相序校准。低占空比运行前，先记录 ADC 零偏、电流正负方向和三相电流在静止状态下的偏差；如果电角度方向、相序或电流符号有一项错误，电机可能表现为抖动、反转、快速升流或一使能就触发保护。第四步再进入开环低速，逐渐增加占空比，观察 PWM、相电流、转速和母线电压；确认开环方向正确后，才把速度环和 Iq_ref 接入。

最后才执行 100 rpm、300 rpm 和自动序列。每组测试开始前发送 X 清状态，测试中保留原始 VOFA 数据，结束后再次发送 X 并确认 PWM=0、R_EN=0、ref_rpm=0。如果硬件 TIM1 Break/COMP 保护还没有实测打通，不应把软件 abort 当作完整的硬件过流保护；在更高功率测试前，需要单独验证比较器触发、Break 输入和 PWM 关断延迟。

验证结果

后期验证重点放在 100 rpm 和 300 rpm。最终 hs300 组日志里，100 rpm 保持、300 rpm 保持和 86 s 自动序列都没有触发 fault/abort，测试结束后也都回到了 idle 安全状态。

测试 命令 目标 最高速度 late MAE 电流特征 结果
100 rpm 保持 M 100 rpm 105.24 rpm 1.503 rpm 无 fault/abort 通过
300 rpm 保持 H 300 rpm 308.47 rpm 3.805 rpm P95 约 2.01 A，峰值记录 17.93 A 通过
自动序列 G 10/100/300 rpm 308.80 rpm 29.060 rpm P95 约 1.33 A，峰值记录 20.71 A 通过

这里要特别说明：G 自动序列的 late MAE 不能直接当成 300 rpm 稳态误差，因为它包含 profile 切换和零速区间；判断 300 rpm 保持能力时，H 日志更有代表性。current_abs_peak_a 也不能单独作为“持续过流”结论，它更像 20 kHz ISR 内的尖峰诊断字段，需要和 P95/P99、瞬时电流、fault/abort 一起看。

这版程序的收获

这次 AXDR_L 程序最有价值的地方，不是某一个 PID 参数，而是把控制、保护和证据链分开了：

  1. 电流环只从 ADC1 三相电流完成回调进入，避免重复 FOC 调度。
  2. 速度环只输出 Iq_ref，不直接改 PWM，使 1 kHz 外环和 20 kHz 内环边界清楚。
  3. MT6816 电角度校准、减速比换算和速度估计都进入遥测，便于排查角度问题。
  4. LCD 显示当前命令、状态和速度曲线，现场不依赖电脑也能做基本判断。
  5. Python 脚本固定测试流程、阈值和 summary 字段，让每次调参有可比数据。
  6. 低/中/高速分段参数比单一参数表更适合 M2006 这种带减速箱、低速摩擦明显的对象。

后续可以继续补的地方

当前版本已经能支撑课程设计和阶段复盘，但如果继续往更大功率、更高速度或长期运行走，还需要补几件事：

  1. TIM1 Break/COMP 硬件过流链路仍应实测打通，不能只依赖软件 abort。
  2. 300 rpm 阶跃和脉冲还有明显瞬态误差，后续可以单独调高动态响应，但要保持电流边界。
  3. 电流环解耦目前关闭，更高转速或弱磁前要重新检查 Vd/Vq 余量和角度延迟。
  4. 如果 MT6816 换到输出轴，减速比、unwrap、速度估计和电角速度换算必须同步重审。
  5. 当前参数绑定 AXDR-L、M2006、MT6816 和当前台架负载，不适合直接复制到其它无刷电机。

总结

AXDR_L 无刷驱动程序目前已经从“能跑 Demo”推进到了“能闭环、能停机、能记录、能复现”的状态。它把 Simulink 的 FOC/速度环思路落成了 STM32G474 上的实机控制链：MT6816 位置反馈、1 kHz 速度环、20 kHz Id/Iq 电流环、Clarke/Park/SVPWM、TIM1 三相互补 PWM、USB CDC 命令、LCD 曲线显示和 VOFA/Python 验证脚本。

从工程角度看，这版程序最大的意义是把“电机转起来”拆成了可检查的状态：采样是否可信，角度是否对齐，电流环是否稳定，速度环是否可控，保护是否能停住，日志是否能复现。做到这一步，后续再谈更快响应、更高转速或无感观测器，才有可靠的基线。

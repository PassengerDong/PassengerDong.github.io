基于 AI8051U 的四合一电调

AI8051U + AM32 移植固件的四合一电调方案，记录默认参数使用、PWM 协议和 DShot 落地限制。

UPDATED 2026.09.22STCBLDCAM32

迁移来源：OSHWHub 开源工程
项目定位：基于 AI8051U 主控和 AM32 移植固件的四合一 ESC，仅供学习与开源交流使用。

项目简介

本项目是一款基于 AI8051U 作为主控芯片、移植 AM32 固件的四合一电子调速器。开源版本已经过上机实测，运行稳定，响应速度能够满足全国大学生智能车竞赛等场景使用。

PCB 在手工焊接上做了一定优化，但整体仍然有难度，尤其是 QFN 和 0402 元件较多。这个项目更适合作为电调硬件设计、功率/信号隔离、固件移植和烧录调试的综合案例。

结构设计

工程采用功率板和信号板分离的双四层板叠层设计，一方面减少信号互扰，另一方面保证功率路径和散热空间。该结构也尽量贴合嘉立创免费打样规则。

实测满足五寸机飞行需求，温升不明显。工程说明中记录 40A 输入电流可以稳定运行，峰值测试到 80A 没有问题。如果后续想进一步优化功率能力，可以考虑增加 GND 和 DCBUS 层，但六层板需要重新评估打样成本和规则。

机械与安装

电调安装孔位兼容常见穿越机 30.5mm 大孔尺寸，可以适配 Mark5 等公模穿越机机架。对于逐飞、龙邱等车模机架，需要通过 3D 打印件或转接结构配合安装。

板子尺寸较小，散热表现较好。板载 MLCC，同时预留固态电容焊接孔，方便根据输入电压、线长和负载冲击补足母线电容。

固件与协议

本工程使用开源 AM32 移植固件，原始固件参考工程为“STC 电调(AM32 固件移植)”。AM32 本身是由社区维护的开源电调平台，本项目尝试在 AI8051U 上适配使用。

实际使用中 AM32 保持默认参数即可；如果用于无人机，也可以先直接使用默认参数，不需要为基础起飞和常规油门响应额外修改复杂参数。

DShot 没有继续作为可落地方案。主要原因是移植后的 AM32 固件程序本身比较复杂，对 8051 的资源负载较大；同时 8051 缺少实现 DShot 所需的关键硬件支持，稳定落地难度较高。因此当前以 PWM 协议作为更现实的使用方案。

烧录方式

信号板预留了 1.27mm 间距的 4P 串口焊盘，可以配合 1.27mm 4P 弹簧顶针下载。使用 STC-ISP 时，先点击下载，再把弹簧顶针戳到焊盘上即可完成识别和烧录。

如需检查或写入固件参数，可使用 ESC_config_tool；基础使用保持 AM32 默认参数即可。根据原工程说明，TX 和 RX 短接后再用戳针即可进入后续烧录流程；建议在 CH340 模块上加一个开关，用来切换 TX/RX 是否短接。

栅极驱动与供电

栅极驱动器使用 FD6288Q，主控使用 AI8051U QFN64。栅极驱动器使用独立降压芯片供电，选用 SY8303，可以支持最高 40V 输入和 3A 电流。SY8303 输出约 9V 给 FD6288Q 供电时，可以支持 3-6S 输入范围。

LDO 采用 SPX3819，最高可承受 16V 输入。

本项目测试使用 4S 电源系统，运行良好。

电流采样与接口

板上带有电流采样，使用 INA199 + 0.25mR 采样电阻。信号接口使用 SH1.0 8P 接头，和常规四合一电调接口兼容，同时额外留了一个 5V 接口，方便给调速器供电做简单测试。

PCB 细节

PCB 上预留了二维码白油位置，可用于放置嘉立创码或版本标识，避免影响主要器件和关键信号区域。

从 AM32 移植工程看软件边界

本地 AM32_AI8051U 工程把 AI8051U 的资源分成了几条相对清晰的路径：PWMA 输出三组互补 PWM，PWMB 用于捕获外部油门信号，ADC 负责电压和电流采样，内部 OPA / BEMF 相关输入参与转子位置判断，TMR0/TMR1 参与换相计时，TMR4 负责周期任务，UART 用于串口遥测。

在当前 target 配置中，工程把电流采样和电压采样分别放在 ADC 通道，并为电流比例、电压分压系数、死区时间和堵转保护周期留下了宏定义入口。这个信息对复刻很重要：硬件原理图上的采样电路和固件真正使用采样值不是一回事，必须同时检查 targets.h、adc.c 和上层保护逻辑。

原始移植说明还明确写到，当前版本虽然保留了电流、电压采样的硬件和配置入口，但固件侧的采样功能并没有完全做完。因此本文把“板上有 INA199 与 0.25mR 采样电阻”和“当前固件已经用采样值完成闭环保护”分开描述，不能因为 PCB 上存在采样链路，就直接宣称软件已经完成过流保护。

PWM、DShot 与实际使用建议

这块四合一电调的现实落地方案仍然是 PWM。AM32 的移植工程保留了 DShot 相关结构，但在 AI8051U 平台上，DShot 需要精确的输入捕获、时序和资源调度，移植复杂度明显高于普通 PWM。对于智能车、实验台和初次复刻，建议先使用稳定的 PWM 输入验证电机启动、停机和方向，再把 DShot 当作单独的后续课题，而不是一开始就同时排查协议、功率级和换相问题。

PWM 验证时可以先使用约 1ms 的停机输入，确认输入端不会悬空；随后以很小的步进增加高电平时间，观察四路电调是否能分别响应。若四路同时连接，仍应先保持低油门，确认公共 5V、地线和信号参考没有明显波动，再逐步扩大负载。

Bootloader 与固件地址

AI8051U 版本使用 AM32 Bootloader，空片首次需要通过 STC-LINK1、串口或内部 USB 将 Bootloader 写入芯片。完成 Bootloader 后，再使用一线串口和 ESC_Config_Tool 进行参数读取、默认参数写入和固件更新。

原始工程的固件更新还涉及应用程序地址偏移：烧录了 Bootloader 后，应用程序不再从空片地址开始运行，而要按 Bootloader 约定放到 0x1000。手动修改 Intel HEX 时，除了修改地址，还必须同步计算校验和。实际操作中更建议使用工程提供的工具或经过验证的脚本，不要直接复制网上的十六进制示例。

复刻后的建议验证表

建议把复刻验证记录成下面几项，而不是只写“能转”：

  • 四路逻辑电源上电后是否稳定，SY8303 输出是否仍接近设计值。
  • FD6288Q 的高低侧驱动波形是否有死区，是否存在上下管同时导通。
  • 四路输入信号是否都能被正确识别，是否有一路因连接器方向错误而反相。
  • 4S、6S 空载和带载时，MOS、驱动芯片、DCDC 和母线电容的温升差异。
  • 采样放大器输出是否超出 MCU ADC 范围，固件是否真的读取并使用这些数值。

这样可以把“硬件设计正确”“固件已经适配”“整机测试通过”三个结论分开，后续继续增加保护功能时也更容易定位问题。

复刻提醒

  • 本工程大量使用 QFN 和 0402 封装，有一定焊接难度，新手慎用。
  • 元器件耐压必须高于输入电源，建议关键器件都选 50V 以上耐压。
  • 打样不需要半孔工艺，但要注意半孔边缘脱落铜皮不要与侧边短接。
  • 螺丝孔存在非地网络，需要套橡胶圈，套上后内孔刚好适配 M3。
  • 固态电容孔位建议按实际线长和输入冲击补齐，不要只依赖板载 MLCC。
